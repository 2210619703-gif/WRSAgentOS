# 厨具的位置和朝向怎么改

日常临时调整请运行 `10_edit_kitchen.py`。它只修改本次运行副本，**重启 05 后恢复默认**；默认文件 `wrs_agent/assets/kitchen/layout.toml` 保持不变。不需要改 Python 或 STL。

`scene.toml` 负责“放什么模型、什么颜色”；`layout.toml` 负责“放在哪里、朝哪个方向”。05 启动时把这两个默认文件复制到 `.local/kitchen-preview/run-*/`，之后只操作运行副本。15 静态预览仍直接读取默认文件。

## 先用终端编辑器：不用直接改 TOML

第一次更新到包含编辑器的代码后，先关闭旧的 05/07，再按下面启动。以后只改摆放时，不用再重启它们。每个终端都要先激活 `wrs` 环境并进入项目根目录。

```powershell
conda activate wrs
cd "D:\WRSAgentOS\WRSAgentOS-latest"

# 终端一：启动场景节点，保持运行
.\scripts\run.ps1 examples/wrs/05_start_node.py

# 终端二：启动观察页面，保持运行
.\scripts\run.ps1 examples/wrs/07_viewer.py

# 终端三：启动摆放编辑器
.\scripts\run.ps1 examples/wrs/10_edit_kitchen.py
```

浏览器打开 **http://127.0.0.1:8000**。终端三会列出厨具的中文名称和 ID，你可以输入列表编号，也可以输入完整名称（例如“大锅盖”）或 ID（例如 `pot_lid`）。相似的两套碗请用编号或 ID 区分。

例如把锅盖移动到 `[0.80, -0.35, 0]`，再绕竖直方向旋转 90°：

```text
输入编号 / 完整厨具名称 / 物体 ID（q 退出）：大锅盖
新位置 X(红), Y(绿), Z(蓝)（回车保留，q 取消本次修改）：0.80, -0.35, 0
新角度 绕X(红), 绕Y(绿), 绕Z(蓝)（回车保留，q 取消本次修改）：0, 0, 90
已应用到本次场景；新的世界位置：[0.8, -0.35, 0.0]
```

**位置单位是米，角度单位是度。** 英文逗号、中文逗号、空格都可以分隔数字；每次必须输入三个数字。回车保留该项原值，输入 `q` 取消当前修改或退出。两个问题回答完后才保存，取消时不会写入一半。

应用后，节点空闲时通常约 1 秒内完成更新；刷新网页即可看到结果，通常不用刷新也会随场景同步。若正在执行动作，会等动作结束后再更新。**退出编辑器后，本次场景继续使用调整后的位置；关闭并重新启动 05，所有厨具恢复默认位置和朝向。** 05 重启后也需重新运行 07，因为观察器绑定的是上一次节点。

```text
默认配置 → 每次启动 05 生成新副本
16 终端编辑器 → 只改本次副本 → 05 自动读取 → 07 同步 → 8000 页面
重启 05 → 从默认配置重新生成 → 临时修改失效
```

编辑子物体时，终端会明确提示“相对于哪个父物体”。例如锅的位置是相对电磁炉的位置；若想连锅带炉一起移动，就选“电磁炉”。两套碗分别选择“碗架”和“碗架（第二套）”，其上方的碗、支架和食物会跟随。

只查看清单、不修改文件：

```powershell
.\scripts\run.ps1 examples/wrs/10_edit_kitchen.py --list
```

必须先启动 05，编辑器才会找到本次运行副本；不存在有效场景时会提示先启动。编辑器只能调整场景物体，不调整机械臂底座。不要手动修改 `.local` 中的场景记录；它们不需要提交 Git。

## 如果以后需要调整“默认摆放”

下面第 1–3 节介绍默认配置的字段和父子关系，便于理解。如果手动修改 assets 中的默认 `layout.toml`，以后每次启动都会使用这些新默认值。**只想临时试位置时，用上面的 16 编辑器即可，不要修改默认文件。**

## 1. 移动一个厨具

以锅盖为例：

```toml
[objects.pot_lid]
pos = [0.75, -0.35, 0.0]
rpy_deg = [0.0, 0.0, 0.0]
```

`pos` 的三个数字依次是 X、Y、Z，单位都是**米**。例如 0.01 是 1 厘米，0.1 是 10 厘米，不要直接填写毫米数。

- X 增大：沿世界坐标向机械臂前方移动。
- Y 增大：向左移动；Y 减小：向右移动。
- Z 增大：向上抬高。当前桌面的上表面位于世界 Z=0。

例如把锅盖向前移动 5 厘米：把第一个数从 `0.75` 改成 `0.80`。

这里的方向对应当前默认机械臂朝向。位置是**模型原点的位置**，不是自动测量出来的最低点；这些厨具网格导入时已归一化，调整倾斜后可能需要重新调整高度。

## 2. 改变朝向

`rpy_deg` 的三个数字依次表示绕 X、Y、Z 的旋转角度，单位是**度**，不是弧度。

```toml
# 平放的锅盖转向 90 度
rpy_deg = [0.0, 0.0, 90.0]
```

平放厨具通常只需要改第三个值。绕 +Z 的正转，从上往下看是逆时针。绕 X/Y 倾斜时，旋转会绕模型原点进行，不会自动保证底部仍贴住桌面。

组合旋转使用固定轴约定 `R = Rz(yaw) × Ry(pitch) × Rx(roll)`；加载器会自动把角度换成 WRS 使用的旋转矩阵。漏勺已换成“立起、中心原点”模型，默认角度为 `[0, 0, 0]`。只修改它的角度并保留位置时，模型中心的世界位置不变；例如 `[0, 0, 180]` 表示绕竖直轴转半圈。它仍跟随捞网架，移动捞网架会带动漏勺一起移动。绕中心旋转不保证任意倾角下都能保持架上支撑。

## 3. 连着移动一整套厨具

配置里已经设置好了跟随关系：

```text
电磁炉 induction_cooker
└─ 大锅 pot

捞网架 skimmer_holder
└─ 漏勺 skimmer

盘子 plate
└─ 盘上长方体 plate_block

第一套碗架 bowl_rack
└─ 碗与支架整体 bowl_support

第二套碗架 bowl_rack_2
└─ 碗与支架整体 bowl_support_2
   ├─ 食物块 bowl_food_1
   ├─ 食物块 bowl_food_2
   ├─ 食物块 bowl_food_3
   └─ 食物块 bowl_food_4
```

例如：

```toml
[objects.induction_cooker]
pos = [0.02, -0.29, 0.0]
rpy_deg = [0.0, 0.0, 0.0]

[objects.pot]
parent = "induction_cooker"
pos = [0.0, 0.0, 0.0450001359]
rpy_deg = [0.0, 0.0, 0.0]
```

电磁炉没有 `parent`，所以它的位置相对世界坐标。锅写了 `parent`，所以锅的位置表示“相对电磁炉原点，向上约 4.5 厘米”。**想把锅和电磁炉一起搬走，修改电磁炉即可。** 旋转电磁炉，锅也会跟着旋转。

想把第二套碗、支架、碗架和四块食物一起向左移动 5 厘米，就把 `bowl_rack_2` 的 Y 从 `0.19` 改成 `0.24`，不需要逐个改食物的位置。

父物体旋转以后，子物体的位置沿着**父物体的坐标轴**计算。例如父物体绕 Z 转了 90°，子物体的局部 +X 偏移就对应世界 +Y。这个跟随关系只是计算摆放位置，不会建立物理焊接、接触或抓取关系。

如果取消 `parent`，必须同时把该物体的位置和朝向换成世界坐标值，不能只删除这一行。

## 4. 检查和看效果

在项目根目录运行，先激活原来的环境：

```powershell
conda activate wrs
cd "D:\WRSAgentOS\WRSAgentOS-latest"

# 只检查配置，打印换算后的世界坐标；不加载 WRS 模型、不连接机械臂
.\scripts\run.ps1 examples/wrs/09_imported_kitchen.py --check-layout

# 加载实际 WRS 模型检查，不启动网页服务
.\scripts\run.ps1 examples/wrs/09_imported_kitchen.py --check

# 查看场景，浏览器打开 http://127.0.0.1:8007
.\scripts\run.ps1 examples/wrs/09_imported_kitchen.py
```

若使用正式 AgentOS 场景，启动方式仍然是：

```powershell
.\scripts\run.ps1 examples/wrs/05_start_node.py
# 在另一个同样激活环境的终端运行
.\scripts\run.ps1 examples/wrs/07_viewer.py
```

05/07 支持本次运行副本的位置和朝向自动更新，修改后刷新 8000 页面即可。05 启动后手动修改 assets 中的默认文件，不会改变本次副本，需重启才能采用新默认值。15 是独立静态预览，读取默认文件，仍需关闭旧预览再重新运行。物体清单、模型、尺寸、颜色或透明度变化需重启 05/07。不要重复启动占用同一端口的服务。

终端编辑器会先校验，再整体替换运行副本，保留原注释和未修改的物体。修改过程中有其他程序同时保存，会提示重新输入。05 重启后会生成不同的副本；旧编辑器中尚未提交的输入不会覆盖新场景。重复启动另一个 05 会被拒绝，不会把正在运行的场景重置。

## 5. 文件分工与常见错误

| 文件 | 用途 |
|---|---|
| `wrs_agent/assets/kitchen/layout.toml` | 默认位置、角度、跟随关系，16 不修改它 |
| `wrs_agent/assets/kitchen/scene.toml` | 模型资产、尺寸、颜色、透明度，以及 `layout = "layout.toml"` 引用 |
| `wrs_agent/scene_layout.py` | 校验配置，把父子位姿和角度换算成世界位置与旋转矩阵 |
| `wrs_agent/scene.py` | 原有场景加载入口，现在会自动读取关联的 layout |
| `examples/wrs/10_edit_kitchen.py` | 终端编辑入口，可直接运行 |
| `wrs_agent/layout_editor.py` | 列出厨具、读取输入、校验并写入运行副本 |
| `wrs_agent/layout_session.py` | 05 创建新副本、标记当前场景、退出时清理 |
| `.local/kitchen-preview/run-*/` | 本次摆放副本；退出清理，重启从默认值开始，不提交 Git |
| `wrs_agent/scene_reload.py` | 05 虚拟节点自动读取摆放；出错时保留原场景 |
| `wrs_agent/assets/fafu/profile.toml` | 机械臂底座和命名姿态，不属于这份厨具配置 |

物体 ID 必须与 `scene.toml` 完全一致；`parent` 也必须填写物体 ID，不能填写中文标签。每个场景物体都要有一条摆放记录，避免漏写后静默消失。数字必须有限，位置和角度都必须恰好三个；父子关系不能形成循环。

新增厨具时，在 `scene.toml` 增加模型定义，再在 `layout.toml` 增加同名摆放项。原来不引用 layout、直接使用 `pos/rotmat` 的其他示例仍然可以运行。

本次初始值保持原场景的 17 个对象和摆放效果。它控制仿真场景，不会发送真实机械臂运动指令，也不会自动做碰撞检测、重力仿真或把结果同步回 Blender。
